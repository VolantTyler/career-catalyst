# Tech stack reporting priorities

## Core stack

The following tools are the **core stack** and should receive special attention in any tech stack research or reporting:

- Cursor
- Gemini
- Hermez
- OpenClaw
- Anti-Gravity

## Reporting rules

When producing a tech stack report:

1. Always separate findings into two sections:
   - `Core stack updates`
   - `Non-core stack updates`
2. Lead with `Core stack updates` even when there are fewer updates there than in the broader ecosystem.
3. Treat the following as especially important for the core stack:
   - product launches and roadmap shifts
   - pricing or packaging changes
   - integrations and ecosystem partnerships
   - adoption signals from jobs, repos, docs, case studies, and engineering posts
   - protocol, runtime, or architecture changes that affect how the stack fits together
4. Keep adjacent tools, competitors, and general market movement in `Non-core stack updates` unless they directly change the outlook for one of the named core tools.

## Naming guidance

- Preserve the canonical names above when summarizing the stack.
- If a source uses a variant or adjacent term, map it carefully and avoid assuming equivalence unless the source makes that relationship explicit.
